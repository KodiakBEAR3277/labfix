# LabFix

LabFix is a lab equipment issue-reporting system: a Laravel + Vue (Inertia) web app in
`backend/` and an Expo Router mobile app in `mobile/` (Expo SDK 54). See `README.md` and
`DEPLOY.md`.

## Key facts

- **Tickets are `reports`.** There is no `Ticket` model — the domain object is
  `App\Models\Report` (`reports` table). Per-ticket history is `ticket_transactions`.
- **Multi-tenancy is shared-schema and app-enforced.** Every tenant table has
  `institution_id`; `App\Traits\BelongsToInstitution` adds a global scope and auto-fills
  `institution_id` on create.
- **Mobile roles:** `student`/`staff` use the `(tabs)` group; `it-support` and `admin`
  share the `(it)` group — there is **no mobile admin zone**. `android/` and `ios/` are
  gitignored and regenerated by prebuild.
- **Brand:** primary teal is `#2dd4bf`. The source mark is
  `backend/public/assets/icons/LabFix Tech Orbit Logo.png` (transparent, full lockup with
  wordmark). Mobile icons/splash/favicon are generated from it by
  `mobile/scripts/generate-icons.ps1`.
- **Equipment status is auto-derived** from open tickets
  (`Equipment::updateStatusFromReports()`), not set manually.
- **EAS builds** require a clean git tree (`eas.json` sets `requireCommit: true`).

## Equipment / QR direction (decided, not yet built)

- Equipment **provisioning stays web-only** (the admin lab modal); no mobile admin zone.
- **QR is our own generated format**, one code per equipment. The mobile app scans it at
  report time to select the right device and jump straight to step 3 of the report form.
  This needs a scanner dependency (e.g. `expo-camera`) + camera permission + a native
  rebuild.
- Nice-to-have: a **printable QR sheet per lab**, and **bulk equipment creation**.
- **Equipment history** = that device's past tickets plus their resolution status, with
  links to open them (no separate service-log table, for now).
- **Mobile photo attachments are deferred**; web stays attachments-only, mobile adds QR
  scanning. A real `attachments` table (with metadata) is a possible later step.
- **Scanned QR payloads are untrusted:** resolve them server-side, never auto-open scanned
  URLs, and support external/foreign codes only via a configured mapping — never by blind
  parsing.
